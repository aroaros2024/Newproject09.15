# ドット絵の決まり（HD-2D 化）

このゲームの絵は、画像ファイルを使わず **TypeScript の関数で組み立てる**。
描き手が何人いても 1 つの絵柄に見えるよう、ここの決まりを守る。
数字の根拠はオクトパストラベラーの調査（主人公 18×32 ドット・点補間・固定の舞台照明）。

---

## 1. 格子と大きさ

- 1 ドット = 画面 3px。床 1 マス = **16×16 ドット**
- 絵はすべて**パレットの番号**で描く（`src/ui/art/palette.ts`）。アンチエイリアス・グラデーション・半透明は**使わない**（光やぼかしは描画の別の層が受け持つ）
- 座標は整数。姿勢の値は小数で動かし、**描く瞬間に `Math.round`** で格子へ落とす

### 大きさの段（`TIER_BOX`、テストで強制）

| 段 | 画用紙 | 足元 (ax, ay) | 待機で見える大きさ | 色数 | 画素の下限 |
|---|---|---|---|---|---|
| S（ネズミ・スライム・コウモリ・鳥・コイン・カエル・小魚・爆弾・茸・草・目） | 24×24 | 12, 21 | 幅 10–20・高さ 8–20 | ≤24 | 60 |
| M（人型・亡霊・鎧・魔導士・弓・吸い取り・封じ・影・ミミック・メタル） | 32×40 | 16, 37 | 幅 14–28・高さ 20–36 | ≤28 | 150 |
| hero（主人公） | 32×48 | 16, 45 | 幅 14–24・高さ 30–34 | ≤28 | 200 |
| L（オーガ・竜・大ウナギ・重い鎧・深淵） | 64×64 | 32, 60 | 幅 28–60・高さ 32–60 | ≤32 | 500 |
| boss | 112×112 | 56, 106 | 幅 60–108・高さ 60–108 | ≤32 | 1500 |

- **足元**はマスの (8, 13) に置かれる点。足の裏がここに来るように描く。**足元より下には何も描かない**（影は描画側が付ける）
- 画用紙の**外周 2 ドットは空ける**（仕上げで輪郭が外へ 1 ドット出るため。さらに 1 ドットの余白）
- 飛ぶ敵：`hover: 6` を付け、6 ドット浮いた位置に描く（足元の点より上）。影は地面に残る
- 水の敵：`submerge: 4` を付けると下 4 ドットが水に沈んで見える
- 系統の中の段階（あおプルン → みどり → くろ → キング）は **同じ形のまま**、色の階調・角・冠・鎧板・大きさ（+2〜6 ドット）で差を付ける

## 2. 光

- **舞台照明は左上・手前から**。全部の絵で同じ
- 面の明るい側（上と左）、暗い側（右下 1/3）、顎・腕・裾の下に 1 段暗い陰
- 輪郭・リムライト・右下の縁は **`finalize()` が自動で付ける**（`src/ui/art/shade.ts`）。自分で描かない
  - 輪郭：形の外側 1 ドット。隣の色の階調の 0 段目。上と左の輪郭は 1 段目（光の側）
  - リム：形の左上の縁を 1 段明るく
  - 影の縁：右下の縁を 1 段暗く
  - 光る色（`EMISSIVE`：火の明るい段・魔法の明るい段・金の最明・空の最明・白）は縁取らない
- 左向きは右向きを**反転してから** `finalize` するので、光はいつも左上から

## 3. 塗り

- 材質 1 つに **3〜4 段**：地 = 3、影 = 2、深い影 = 1、明るい = 4。**5 段目は金属・宝石・目の光だけ**
- 真っ黒は使わない（パレットに無い）。一番暗いのは各階調の 0 段目
- ディザは 2×2 の市松だけ、大きな面（L・boss・地形）だけ
- 線は**二重点を作らない**。`line()` は Bresenham なので大丈夫。曲線は 1:1・1:2・2:1・1:3 の段で
- 目は 1×2 か 2×2 の暗い点 ＋ 1 ドットの光（白か明るい段）。目が読めることが一番大事
- 系統ごとの色の組は `Variant.ramps`（材質名 → 階調）で決め、`mat(v, '体', 段)` で色を取る

## 4. 向き

| リグ | 描く向き | 反転 |
|---|---|---|
| 主人公 | S・SE・E・NE・N（5） | SW・W・NW |
| 多くの敵 | S・N・E（3）。斜めは E | 西側 |
| 形が丸い敵（スライム・目・植物・仮面） | S だけ（1） | 西向きは反転 |

`E` は**右向き**に描く。`build(b, pose, dir, v)` の `dir` のとおりに描けばよく、反転は呼ぶ側がする。

## 5. 動き（コマ数）

| 動き | 主人公 | 敵 | 使う曲線（`src/ui/art/anim.ts`） |
|---|---|---|---|
| idle 待機 | 4 コマ・4fps | 4 コマ・4fps | `idleBreath()` — 胴と頭だけ 1 ドット上下、足は動かさない |
| walk 歩き | 8 コマ | 小 4（`hop`）/ 中・大 6（`walkCycle(6)`） | 進んだ距離でコマが進む |
| attack 攻撃 | 6 コマ・15fps・当たり 2 | 5 コマ・15fps・当たり 2 | `attackSwing()` / `lunge()` — 溜め → 当たり（1 コマ、明るい色の残像を 1 本）→ 戻り |
| cast 詠唱 | 6 コマ・12fps・当たり 4 | 魔法を使う敵だけ | `castRaise()` — 杖を掲げ、宝石が光る（`pose.glow`） |
| hurt 被弾 | 2 コマ・12fps | 同じ | `hurt()` — のけぞる・目を閉じる |
| sleep 眠り | 2 コマ・2fps | 同じ | `sleep()` |
| use 道具 | 4 コマ・12fps | — | `useItem()` |

- ループする動きは**少なくとも 2 コマが違う絵**であること（テスト）
- 倒れる動き（光る → 崩れる）は描画側が自動で作る。描かなくてよい
- 羽ばたきは `flap()`（`pose.fx` が翼の角度 -1〜1）

## 6. 主人公ナギ

- **笠（黄土・藁）と青い合羽**。今の 16×16 の絵と同じ人物
- 見えるのは 18×32：笠を含む頭 11×10（笠のつばは幅 16）・胴 9・脚 10。約 2.6 頭身
- 合羽の裾と、首に巻いた布の端が `pose.sway` で揺れる。腰に刀
- 目は 1×2 の暗い点。笠の影が顔の上 1〜2 ドットにかかる

## 7. リグの書き方

```ts
// src/ui/art/rigs/slime.ts
import { type Rig, type Pose, type DrawDir, type Variant, mat, registerRig, registerSpecies } from '../rig.js';
import { hop, idleBreath, lunge, hurt, sleep } from '../anim.js';
import { ellipse, rect, runs, type PixBuf } from '../pixbuf.js';

const slime: Rig = {
  id: 'slime', tier: 'S', dirs: 1,
  anims: { idle: idleBreath(), walk: hop(), attack: lunge(), hurt: hurt(), sleep: sleep() },
  build(b: PixBuf, p: Readonly<Pose>, _dir: DrawDir, v: Readonly<Variant>): void {
    const cx = 12;
    const foot = 21 + Math.round(p.bob);
    const rx = 7 + Math.round(p.sqX) + (v.grow ?? 0);
    const ry = 6 + Math.round(p.sqY) + (v.grow ?? 0);
    ellipse(b, cx + Math.round(p.lean), foot - ry, rx, ry, mat(v, 'body', 3));
    // …影・光・目は runs() で手描き
  },
};
registerRig(slime);
registerSpecies({
  slimeBlue: { rig: 'slime', variant: { ramps: { body: 'water', eye: 'ink' } } },
  slimeKing: { rig: 'slime', variant: { ramps: { body: 'water', eye: 'ink', crown: 'gold' }, grow: 3, flags: 1 } },
});
```

- ファイル 1 つ = 系統 1 つ。**自分の担当ファイル以外は触らない**。`rigs/index.ts` に 1 行 `import './slime.js';` を足す
- 使ってよいのはパレットの色だけ（`mat()` か `ci()`）。16 進の色を直接書かない
- 使わない引数は `_dir` のように `_` を付ける（`noUnusedParameters`）
- ゲームの乱数（`world.rng`）と `Math.random` は**使わない**。ばらつきは `hash2()`（`src/ui/art/hash.ts`）
- DOM（`document`・canvas）に触れない。テストが node で全部の絵を描いて検査する

## 8. 見本帳で確かめる

```bash
npm run build
node tools/shots.mjs --out <保存先> --port <空いている番号> \
  --scenes "art:rig:slime,art:rig:slime&gray=1,art:lineup&tier=S"
```

- `art:species:<id>` 1 種の全部の動き × 向き × コマ（4 倍）＋ 実寸 3 倍を 3 つの背景で
- `art:rig:<id>` そのリグを使う全部の種
- `art:lineup` 全部の種の待機（手前）を段ごとに。`&tier=M` で絞る
- `&gray=1` 明るさだけで見る（形と明暗が色に頼らず読めるか）

### 採点の観点（画像を見て確かめる）

1. 実寸（3 倍）で**何の敵か分かる**。影絵だけでも系統が分かる
2. 系統の中の段階の違いが見て分かる
3. 光が左上から。リムと影の縁の向きが揃っている
4. 孤立した 1 ドットのゴミ・二重点・ギザギザの曲線が無い
5. 目が読める
6. 攻撃の当たりのコマが一目で分かる（溜め → 伸び）
7. 足が足元の赤い目印に乗っている。飛ぶ敵は浮いている
8. 明るさだけで見ても、胴・頭・手足が分かれて見える
9. 色数が段の上限以内

## 9. 地形

- 床の変化は 4 種類以上、明暗の差は 2 段まで。模様（ひび・苔・骨・草・水晶）は全体の 15% 以下
- 壁は 3/4 見下ろし。床に面した壁は **正面 12 ドット ＋ 上の縁 4 ドット**を壁のマスの中に描く（前後の重なりを気にしなくてよい）。正面の下 1 ドットは 0 段目、下の床に 2 ドットのディザの陰
- 液体は 4 コマ、岸には泡や土手。穴は縁を描く。階段は 16×16 で少し光る。店の床は敷物の模様
- 地形の絵は「種類・部屋番号・出入口・店・階の種・座標」だけで決める（`terrain/types.ts`）。**ワナ・探索状態・暗い部屋・モンスターハウスは読まない**
