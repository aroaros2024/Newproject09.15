# 設計メモ

実装されているルールの要点。数値の出どころは `src/game/rules.ts` と
`src/data/` で、**このファイルではなくコードが正**です。
バランスを触るときは `rules.ts` と `src/data/dungeons.ts` を見てください。

---

## ターン

```
プレイヤーの行動
  → 踏んだマスの効果（ワナ・溶岩・アイテム自動取得）
  → 仲間の行動 → 敵の行動
  → 状態異常（継続ダメージ・残りターン）
  → 満腹度 → HP 自然回復
  → モンスターの自然湧き → 不定の風
  → 視界の再計算
```

速度は「1 ターンを 2 ラウンドに分ける」方式で表す。

| 速度 | 行動するラウンド |
|---|---|
| 通常 | 0 |
| 倍速 | 0 と 1 |
| 鈍足 | 偶数ターンの 0 のみ |
| 2 回攻撃 | 0（攻撃だけ 2 回） |

**ロジックはアニメーションを待たない。** 演出は `GameEvent` としてキューに
積むだけで、描画側が自分のペースで消化する。

## 戦闘

```
命中率   = clamp(0.92 + 命中補正 - 回避率, 0.05, 1.00)
会心     = プレイヤー 1/16（会心の印 +1/16 ずつ、上限 8/16）
           モンスター 1/32
ダメージ = floor( 攻撃力 × (15/16)^防御力 × rand(112..143)/128 )   最低 1
```

- **会心が出ると防御力を 0 として計算する**（＝盾を無視する）
- メタル系は計算後にさらに −20（鋼断ちの印があれば無視）
- 気絶中は受けるダメージ 1.5 倍

```
プレイヤーの攻撃力 = ちから + 武器の攻撃力 + 修正値 + 剛腕の印×2
プレイヤーの防御力 = 盾の防御力 + 修正値
```

**レベルアップで攻撃力・防御力は上がらない。** 上がるのは最大 HP だけ。
攻撃力はちからと武器、防御力は盾でしか伸びない。

## 成長

```
Lv L に必要な累積経験値 = floor( 0.9(L-1)³ + 4.5(L-1)² + 4.6(L-1) )
レベルアップ時の最大 HP 上昇 = 4 + floor(L / 10)
```

| Lv | 最大 HP | | Lv | 最大 HP |
|---|---|---|---|---|
| 1 | 15 | | 30 | 161 |
| 10 | 51 | | 50 | 311 |
| 20 | 101 | | 99 | 848 |

初期値は Lv1 / HP15 / ちから 8。**どのダンジョンでも毎回 Lv1 から始まる。**
永続的に伸びるのは倉庫の装備だけ。

HP 自然回復は 1/1000 単位のアキュムレータで管理する。

```
1 ターンの回復量(×1000) = floor( 最大HP × 1000 / max(50, 150 - Lv) )
```

満腹度 0 のとき、および毒・猛毒のときは回復しない。

## 満腹度

内部では 1/10 単位の整数（`foodX10`）。初期 1000（＝100.0）、上限 1500。
**1 ターンに 1 減る＝100 から 0 まで 1000 ターン。**
0 になると毎ターン HP −1。

減少量は印と腕輪で変わる（剛腕 ×2、疾風 ÷2、腹持ち ÷(1+Lv)、
回復の腕輪 ×2、ハラヘラズ 0）。合成後の上限は 6。

## 未識別

草・巻物・杖・壺・腕輪の 5 カテゴリが対象。冒険のたびに
仮の名前（色・意味不明な語・模様・形・素材）をシャッフルして割り当てる。

判明する条件: 使う / 店で売る / 識別の巻物・壺・腕輪 / 山菜おにぎり。

武器と盾は種類こそ分かるが、**修正値は装備するまで分からない**
（`鉄の剣+?` と表示される）。

---

## 印

`ItemInstance.runes` は同じ印 id を重複して持てる。

- **使用スロット数 = 異なる印 id の数**
- **印のレベル = その id の出現回数**

これで「重ねられる印は 1 スロットのまま強くなる」を、
追加のフィールド無しで表現している。合成の壺は修正値を足し、
素材の印を入る順に移す。匠の印は先に入れるとスロットが広がる。

排他のペア: 剛腕↔疾風、腹持ち↔鈍足、必中↔会心。

## フロア生成

```
1. マップを gridCols × gridRows の区画に切る（切れ目は揺らす）
2. 各区画に部屋を置く。一部は部屋を持たない「合流点」にする
3. randomized Kruskal で全域木を作り必ず全連結にする
4. さらに 25% の余分な辺を足してループを作る
5. 部屋の無い区画の行き止まりを、変化が止まるまで繰り返し刈る
6. 区画の境界に沿って通路を掘る（コの字 / L 字）
7. 水路・溶岩は部屋の内側にだけ置く
8. 連結性を検査し、壊れていれば別シードで作り直す
```

**7 が肝**: 部屋の外周 1 マスを必ず床で残すので、液体で通行不能になることが
原理的に起きない。部屋の最大サイズは 11x8 に制限している。これが無いと
部屋が区画を埋め尽くして「4 分割された画面」に見え、通路の面白さが消える。

視界は光線追跡ではなく**部屋単位**。明るい部屋では部屋全体と壁・出入口が
見え、暗い部屋と通路では周囲 8 マスのみ。出入口に立つとその部屋が見える。

## 難易度の組み立て

どのダンジョンでも Lv1・HP15 から始まるので、**深いダンジョンほど
序盤の敵を弱くしないと 1F で即死する。**

- 1〜3F では、そのダンジョンの想定装備で **3 発は耐えられる**強さに収める
  （`test/data.test.ts` が検査する）
- 初期配置のモンスター数は階層とともに増え、最深部の 1/3 で既定値に達する
- 武器か盾を持たずに出発しようとすると、村が**ダンジョン相応の装備を貸す**
  （木の棒 → 鋼の剣）。これが無いと一度死んで身ぐるみを失った時点で
  深いダンジョンへ戻れなくなる

アイテムの出現表は「値段が高いものほど深い階から出る」規則で自動生成する
（`itemTable()`）。ダンジョンを足しても手書きの表が肥大化しない。

## セーブ

| 種類 | 内容 | 消えるとき |
|---|---|---|
| 村 | 倉庫・ギタン・クリア状況・記録 | 「はじめから」を選んだとき |
| 中断 | 冒険 1 回分（乱数の状態を含む） | 冒険が終わったとき |
| 設定 | 音量・速度・操作 | 「はじめから」を選んだとき |

中断データは JSON を往復する。**Map / Set / class を混ぜてはいけない。**
乱数の状態（`RngState`）も載るので、再開しても同じ続きが再現される
（`test/save.test.ts` が検証している）。

読み込みは必ず検証し、壊れていれば既定値に落とす。
localStorage が使えない環境でも、保存できないだけで遊べる。

## 拡張するとき

| やりたいこと | 触るファイル |
|---|---|
| アイテムを足す | `src/data/items/*.ts` ＋ `src/game/itemEffects.ts` に効果 |
| モンスターを足す | `src/data/monsters.ts` ＋ `src/ui/sprites/monsters*.ts` に絵 |
| 特技を足す | `src/game/monsterSkills.ts` |
| ワナを足す | `src/data/traps.ts` ＋ `src/game/trapEffects.ts` |
| ダンジョンを足す | `src/data/dungeons.ts` ＋ `DUNGEON_ORDER` と `LOANER_GEAR` |
| バランスを調整する | `src/game/rules.ts` |

`registry.ts` の `validateData()` が起動時に id の重複・参照切れ・
初期印のスロット超過・仮名プールの不足を検査する。
テストは効果 id に実装が対応しているかも見るので、
**綴りを間違えたまま黙って無効になることはない。**
